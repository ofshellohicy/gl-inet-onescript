# OpenClash 订阅节点地区排除检查

本文记录如何判断一份 OpenClash 配置是否真正排除了香港、澳门、台湾和新加坡节点。检查节点清单、代理组和订阅更新机制，不能只看 LuCI 中填写的“排除关键词”。

## 2026-08-18 实机结论

检查对象是 GL-MT3000 上保留的原配置 `/etc/openclash/config/config.yaml`。检查期间活动配置为另一份 `frank-us-home.yaml`，未切换、修改或重启原配置。

### 当前配置快照

- 静态节点：48 个。
- 代理组：2 个，一个 URL Test 组包含 48 个节点，一个 Select 组包含相同节点及自动选择组。
- 节点协议：HTTP 16、Hysteria2 21、VLESS 11。
- 节点地区：美国 22、日本 10、英国 4、德国 3、澳大利亚 2、加拿大 2、印度尼西亚 2、印度 2、法国 1。
- 香港、澳门、台湾、新加坡节点计数均为 0。
- 规则：7,999 条，其中 7,173 条进入 `Proxy`，826 条为 `DIRECT`。

因此，“当前这份 YAML 没有四地区节点”已经确认。

### 策略确认

用户已确认原配置按当前状态验收为 OK。预期策略是排除香港、澳门、台湾、新加坡节点，并有意排除名称带奈飞标识的节点；`奈飞` 不是误填关键词。本次不修改该配置。

### 订阅设置

OpenClash 订阅项处于启用状态，配置名为 `config`，当前设置为：

```text
sub_convert=0
ex_keyword=香港 台湾 奈飞 新加坡
```

这里仍有两个更新边界：

1. 排除词没有澳门、澳門、Macau 或 Macao。
2. OpenClash 当前脚本只在 `sub_convert=1` 时把 `ex_keyword` 编码进订阅转换请求；`sub_convert=0` 时直接下载订阅地址。本机订阅地址本身也没有查询参数或排除参数。

所以当前配置可以继续使用，但不能仅凭这些 UCI 字段证明未来订阅更新仍会排除四地区。当前没有澳门节点，可能是上游本来没有，而不是本机规则成功过滤；这条说明用于后续复核，不代表当前配置需要立即修复。

## 正确验收方法

每次订阅更新后都应同时检查：

1. `proxies` 中四地区节点数量是否为 0。
2. `proxy-groups[*].proxies` 中是否仍引用四地区节点。
3. `proxy-providers` 或代理组是否存在有效的 `filter` / `exclude-filter`。
4. OpenClash 订阅是否开启转换；未开启时，LuCI 的 `ex_keyword` 不构成实际过滤保证。
5. 上游订阅 URL 是否自身提供排除能力。检查时只记录参数名，不记录 URL、令牌或源订阅地址。

“排除节点”只影响可选代理服务器，不等于阻止访问香港、澳门、台湾、新加坡的目标网站或 Netflix 服务。

## 建议的地区匹配范围

如后续启用订阅转换，应覆盖常见中英文名称、国家/地区代码和旗帜：

| 地区 | 建议覆盖 |
| --- | --- |
| 香港 | `香港`、`Hong Kong`、`HK`、`HKG`、`🇭🇰` |
| 澳门 | `澳门`、`澳門`、`Macau`、`Macao`、`MO`、`MFM`、`🇲🇴` |
| 台湾 | `台湾`、`台灣`、`Taiwan`、`TW`、`TPE`、`🇹🇼` |
| 新加坡 | `新加坡`、`狮城`、`獅城`、`Singapore`、`SG`、`SIN`、`🇸🇬` |

两字母代码应使用单词或分隔符边界，避免 `HK`、`TW`、`SG` 误匹配普通节点名称。实际启用转换前，应 dry run 新订阅并比较节点数量、协议和代理组，不能直接覆盖当前可用配置。
